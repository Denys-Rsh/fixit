=====
Fixit
=====

Сервісний центр: облік ремонту техніки в Odoo 19.

Модуль веде замовлення на ремонт: клієнт здає пристрій, замовлення
призначають майстру, у замовленні є рядки робіт, а по замовленнях
друкується PDF-звіт.

Встановлення
------------

* Скопіюйте папку ``fixit`` у ``custom_addons``.
* Оновіть список застосунків і встановіть **Fixit**.
* Для тестових даних створіть базу з увімкненими демо-даними.

Запуск тестів::

    odoo -d test_db -i fixit --test-enable --stop-after-init

Стани замовлення
----------------

Стан не редагується напряму: у формі він лише для читання, у канбані картки не можна перетягувати
між колонками. Змінити його можна тільки кнопками в шапці форми. Кожна кнопка перевіряє перехід
за словником ``NEXT_STATES`` у ``models/order.py`` і для забороненого переходу показує помилку.

.. code-block:: text

   New Request → Diagnostics → Customer Approval → In Repair → Ready → Picked Up
                                       │               ↑
                                       └→ Awaiting Parts┘

   Cancelled — з будь-якого стану до «Ready» (не включно).
   Picked Up і Cancelled — кінцеві, з них виходу немає.

Демо-замовлення створюються одразу в потрібному стані, щоб заповнити всі колонки канбану.

Інваріант предметної області
----------------------------

Кількість у рядку робіт завжди більша за нуль: рядок з нульовою чи від'ємною кількістю
не має сенсу і псує суму замовлення. Його захищає обмеження бази ``CHECK(quantity > 0)``
у ``models/order_line.py``. Умова проста й стосується одного поля, тому PostgreSQL перевіряє
її атомарно при кожному записі, і її не обходять ні імпорт, ні RPC, ні паралельні транзакції.
``@api.constrains`` тут зайвий: він потрібен для довільної логіки, але працює лише в межах
транзакції Odoo і вразливий до гонок. Перевірка лише у формі була б найслабшою, бо її
обходить будь-який запис не через інтерфейс.

Права доступу
-------------

* **Fixit / User** — читає, створює й змінює свої замовлення та пристрої клієнтів; запчастини й типи пристроїв лише читає.
* **Fixit / Admin** — повний доступ до всіх записів і масове перепризначення майстра.

Переклад
--------

Файли в ``i18n/`` експортовано самим Odoo, а не написано вручну. Щоб оновити їх після зміни рядків:

.. code-block:: bash

   odoo-bin i18n export -c config/odoo.conf -d odoo -l uk_UA pot -- fixit

Далі заповнити порожні ``msgstr`` в ``i18n/uk.po`` і оновити модуль з ``--i18n-overwrite``.
